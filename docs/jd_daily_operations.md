# 面向电商与商品运营实习的项目优化

本轮围绕所提供JD中的日常运营、商品维护、ERP数据处理、用户调研和临时事务，补充执行与交接功能。分析数据的性质沿用原项目：公开内容与商品快照、匿名便利样本问卷、模拟ERP分别记录。

## 已实现的对应功能

| JD工作 | 项目中的操作 | 可展示的产出 |
| --- | --- | --- |
| 日常电商与商品运营支持 | 从运营简报建立商品复核、ERP核对、调研待办，填写负责人、截止日期及优先级 | 待办列表、逾期筛选、处理历史 |
| 商品信息维护 | 在待办中打开商品依据，进入已有商品主档维护与变更记录 | 字段修订及证据记录，任务中的交接说明 |
| ERP数据处理 | 从模拟ERP分析生成核对待办，进入补货模块继续检查 | 统计口径与异常核对结果；不等同于真实采购执行 |
| 衍生品用户调研 | 根据已有问卷的品类、价格与购买阻力建议建立任务 | 后续访谈或专项验证事项，保留便利样本局限 |
| 临时事务与沟通跟进 | 手工登记事项、验收要求、待协助原因及完成结果 | 接手人可查看的处理历史与当前交接表 |
| Office资料整理 | 按当前已应用筛选导出中文字段CSV，Excel可直接打开 | 可筛选的交接明细；CSV本身不包含数据透视表或格式模板 |
| 抖音直播加分项 | 生成直播前货品、价格、授权、库存、交期、优惠与FAQ准备清单 | 明确标记为演练，不生成开播或成交业绩 |

## 使用方法

运行已有平台后，进入侧栏“日常运营待办”（`/#tasks`）。

1. 点击“从运营简报建立待办”：首次生成3项工作，全部为待处理，负责人和日期留空。重复点击保留原记录及处理进度；已完成事项也不自动重建。任务保留创建时简报快照，后续分析变化不覆盖旧记录。
2. 打开“处理 / 记录”：补充实际跟进人、截止日期、工作内容和验收要求。每次保存都要填写进展说明。
3. 开始处理或标记完成前必须填写负责人。标记“待协助”或“已完成”时至少填写10字，分别说明阻塞原因与所需协助，或处理结果及核对依据。字段校验不能代替人工验收。
4. 可查看处理历史，包括更新前后记录、负责人、截止日期和版本。旧窗口保存会提示版本冲突，关闭并刷新后重新编辑。
5. 按类别、状态、关键词或逾期筛选，再导出交接表。CSV与列表使用同一组已应用条件；只修改筛选输入但未点击“筛选”不会改变导出范围。导出包含最新进展，完整历史在页面查看。
6. 临时事务用“登记事项”；直播准备用“直播准备清单”。演练时在标题或记录中注明演练，实际执行后再登记结果。

日期采用北京时间，截止当天尚未逾期；已完成任务不计入未完成逾期。负责人是本地自由填写字段，当前项目没有团队账号、权限或真实指派通知。

## 三分钟面试演示

- **前40秒：说清业务问题。**“已有平台能分析商品、用户和订单，我进一步补了待办和交接，便于把分析建议落实为具体核对工作。”在运营总览展示三类数据各自来源。
- **40—90秒：展示商品维护。**从简报建立待办，打开商品维护任务，再进入公开商品档案。说明角色、规格、授权资料需要逐项核对；使用演练记录展示修改原因和版本。
- **90—130秒：展示跟进沟通。**填写负责人、日期，将某项工作置为“待协助”，写清缺失资料和所需支持，查看处理历史。不能仅因系统允许改状态就宣称已解决业务问题。
- **130—160秒：展示交接。**筛选尚未完成的商品维护事项，导出CSV。解释交接表包含事项、负责人、截止日期、验收要求、最新进展及数据性质。
- **最后20秒：说明岗位匹配。**“这体现了数据整理、信息维护和事项跟进能力。ERP来自模拟数据；直播目前完成准备清单演练，尚无真实渠道后台运营经历。”
