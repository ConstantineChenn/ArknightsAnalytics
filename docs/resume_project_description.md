# 简历项目描述

## 项目名称

Arknights Analytics｜《明日方舟》IP周边选品与商品运营分析平台

个人项目｜2026.09—至今｜[代码仓库](https://github.com/ConstantineChenn/ArknightsAnalytics)｜[本地演示](http://127.0.0.1:8765/)

localhost只能在本机访问，投递时写“面试现场演示”，不要冒充已部署公网演示。当前前端与运营简报更新尚未推送GitHub。

## 技术栈

Vue 3 / Vite / FastAPI / Python / Pandas / NumPy / SQL / SQLite / Excel / Matplotlib / pytest；配套Redis / Nginx / Prometheus / Docker Compose部署配置

## 推荐简历版本

- **业务与平台开发：**针对周边选品依赖经验、商品资料分散及经营数据难以核对的问题，使用Python/Pandas固化清洗与统计流程，SQL关联商品、订单及售后，以Vue 3、FastAPI和SQLite构建7个功能模块，支持维护、对账、导出及3类基于证据的运营简报，将分析落到可核查的工作事项。
- **用户需求与选品：**整合549条B站官号内容、100条微博官号内容和84条淘宝公开商品快照，结合243份真实匿名问卷，拆分729条角色偏好排序与1,701条品类价格观测；通过角色归因、加权排序和分群分析形成角色、品类与价格带建议，保留样本量与来源，避免将内容热度直接等同于购买需求。
- **商品信息维护：**为统一编码、价格、授权与履约口径，建立19项字段规范，维护210个模拟内部SKU与83个去重公开商品档案；使用字段白名单、联合规则校验与版本锁实现单条编辑、最多500条CSV批量预检和字段级审计，识别75条需复核商品任务，支持异常筛选及工作主档导出。
- **ERP处理与运营复盘：**围绕7类模拟ERP业务表关联6,000张订单、7,652条明细与392条售后记录，通过SQL视图与Python汇总完成头明细金额核对、库存分群、补货预算和7类渠道经营比较；区分订单支付率、退款金额率与毛利代理，将结果转为复核建议，不将模拟数据写作真实经营收益。
- **决策验证：**为60名角色设计209组权重与去源情景，形成12,540条排名观测；审计10个多角色商品链接的身份歧义，保留人工复核；采用订单粒度CTE预聚合，验证多表关联下的金额守恒，避免将公开商品链接误作规格SKU、将问卷意愿误作销量。
- **验证与交付：**建立29个业务视图、35个索引及可追溯来源说明；完成149项pytest自动化测试，总体语句覆盖率79.82%，前端生产构建通过。商品修改写入独立SQLite工作层，不回写原始问卷与历史经营快照。

## 一句话介绍

我将公开内容热度、243份匿名用户调研与淘宝商品信号连接到商品主数据、候选试点和模拟ERP经营链路，用Python/SQL完成角色选品、商品维护、价格、渠道、供应商、库存周转、补货和售后分析；真实商业试点结果必须由实际记录触发，不使用模拟数据代替。

## 真实性口径

- 243份问卷经批次所有者确认为真实匿名回收，但属于便利抽样，不代表全部玩家。
- B站、微博、小红书和淘宝数据属于采集时点公开快照；淘宝收货人数按公开下界代理处理。
- ERP订单、库存、采购、售后、收入与毛利均为模拟数据，只用于展示分析方法，不可表述为企业真实经营业绩。

## 技术选择与面试追问

- Python/Pandas相对手工复制粘贴的价值是重复执行、规则留存和来源追踪；Excel仍用于导出协作。没有计时对照，不写“效率提升XX%”。
- SQL/SQLite适用于当前结构化关联和本地单用户规模，用JOIN、业务视图与聚合核对经营数据，不声称企业级高并发能力。
- Vue 3/FastAPI让运营能通过界面筛选、维护、预检和导出，统一服务端校验，不必直接修改脚本。
- 运营简报采用确定性规则，金额、库存和样本口径可重复检查；目前不是LLM Agent，不把后续计划改写成已完成功能。
- 149项测试是测试数量而非Bug数量；79.82%是当前语句覆盖率而非提升幅度。29视图、35索引由SQLite元数据核验。12,540条排名观测是重复计算产物，不是新增公开采样。
- 75条维护任务是待复核事项，不是已解决75个问题。历史293条事件是210条模拟建档加83条快照观测，不是人工完成293次修订。
- 未接入真实抖音后台，不写直播运营实绩、GMV或投流ROI。Redis/Nginx/Prometheus/Docker Compose仅为配套配置，不占据主篇幅。
